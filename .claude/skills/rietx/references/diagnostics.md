# 7. The diagnostics are the channel for "your answer is wrong although Rwp is fine"

Load it when a `Diagnostic` fires and you need the row: what it means, what to do, and what you must not do.

*A reference file of the `rietx` skill. The body it belongs to is [`SKILL.md`](../SKILL.md); section numbers are the ones the body cites.*

Every code below is a structured `Diagnostic` on `result.diagnostics` with a
`level`, a `where` list of parameter paths, a `message` and a `suggestion`.
**Branch on the code, not on the message text.**

One namespace note, because two vocabularies share the same UPPER_SNAKE shape:
every code in this document is the **engine's**, a `Diagnostic.code`. The GUI
server's session codes (`NOT_FOUND`, `RUN_IN_FLIGHT`, `STALE_REVISION`, …) are
a separate vocabulary with no rows here, so a code met outside
`result.diagnostics` is the server's, not the engine's.

| Code | What it means you must not do |
|---|---|
| `HIGH_CORRELATION` | Quote both members of the pair as independently measured. Deduplicated across a plan's stages (worst \|ρ\| kept, every stage it fired in named in the message) and capped at 10 per fit, worst first — a `HIGH_CORRELATION_OMITTED` row past the cap gives the omitted count, never a truncated list with no notice |
| `FLAT_DIRECTION` | Quote **either** member as measured, and do not read the esds. This fires when \|ρ\| is 1.000 to the three decimals the message prints, which is a statement about the **rank** of the data rather than a strong correlation: one direction of the pair is not measured at all, and each parameter's esd is conditional on the other being right rather than marginal over it. It rides *beside* the pair's §`HIGH_CORRELATION` row. Tighter convergence does not help: fix one member at an independently known value and refine the other, or free them in different stages, and say which was held. Widening the range or adding a second histogram separates them |
| `FLAT_DIRECTION_OMITTED` | (info) Read it as "only these pairs are degenerate". The flat-direction rows are capped for rendering at the same ten as §`HIGH_CORRELATION_OMITTED`, on their own budget. `result.identifiability` carries the full matrix; nothing was dropped from the fit |
| `COVARIANCE_DIRECTION_DISCARDED` | Quote none of the esds in `where` as measured. Three or more parameters share a direction the solve discards (zero variance), so each esd is at least √2 short, and no pair among them is a §`FLAT_DIRECTION`. Free fewer of them in one stage, hold what is known independently, or widen the range. (Measured: 183 of 1 899 slow-acceptance solves, WP-1535) |
| `HIGH_CORRELATION_OMITTED` | (info) Read it as "nothing was dropped from the fit" — only from this message. `result.identifiability` carries the full correlation matrix and `top_correlations` list for anything past the 10 shown |
| `BOUND_HIT` | Quote a parameter whose bound **carried load** as a measurement. The value sits on a limit the data push it past. `Diagnostic.value` is that push (a signed cosine), so a value near a limit with **no** row here is one the limit is not holding, and widening it buys nothing. `RefinedParameter.at_bound` is the same finding on the row, three-valued: test `is True`, since `None` means untested (a tied row, or `replay`). **Check the ties before you widen a bound**: a tie hands its dependent's limits back to its source, so a `BOUND_HIT` on a parameter whose own `min`/`max` are nowhere near the value is a dependent's ceiling arriving through the tie, and the parameter to widen is that dependent (§ 8.22). A floor of 0 is §`FLOOR_HIT` |
| `FLOOR_HIT` | Report the parameter as absent, or as exactly zero. A scale, width or B ended on its lower bound of 0 (W on its Γ_G² floor) because the data push it below what it can be. Its value and esd stay, and every other esd is marginal over it. Quote an upper limit: `ref.profile_interval(data, path).upper`. Held at 0 and refitted, the others' esds become conditional on it, smaller by √(1−ρ²) each. (Measured: BT-1 `profile.x` 0.0098 marginal, 0.0032 held, WP-1929) |
| `BACKGROUND_ABSORPTION` | Quote ADPs, scales or QPA fractions from this fit — the background can imitate them, and Rwp *improved* while they biased. Read the number, not the bit: `report.background.absorption` is the same measurement for **every** screened parameter, fired or not, and `result.identifiability.background_absorption` carries it on the result. **The R² names the victim, not the cause** — it says what the background could reproduce, never what put it there, and a phase width can be the absorber: a phase broadened past the instrument stops being a set of peaks and becomes a second background, so read `SIZE_UNUSUALLY_SMALL` / `STRAIN_UNUSUALLY_LARGE` and `result.microstructure` on every phase before concluding the background function is the thing to change (measured on a four-phase in-situ scan, WP-1130 § Finding 2; along a series, `SEQUENTIAL_WIDTH_GROWTH`). Le Bail and Pawley screen nothing, so there `report.background.worst_absorption` is `None`: not measured, never clean (WP-1465) |
| `HUMP_TOO_NARROW` | Quote **anything** from a fit whose declared hump has narrowed towards the instrumental resolution — the peak parameters, the displacement parameters it was supposed to protect, or the Rwp. A `HumpComponent` is three free parameters with an unconstrained position, so at a resolution-limited width it is a reflection with no cell and no structure factor behind it, and a free peak improves Rwp whether or not anything is there. `value` is the fitted width as a multiple of the instrumental FWHM at its own position; the feature is for diffuse or amorphous scattering and sample-environment contributions, whose widths come from disorder and run to tens of times the resolution (the case it was built for is ~20×). If there is a real unindexed line at that angle, the honest answers are a second phase or Layer 0's unmatched-peak report — never a hump |
| `EXTRA_PEAK_ON_REFLECTION` | Quote the intensity split between the phase and the declared peak as if it were measured — it is the §3 degeneracy, two terms over one peak. Not wrong by itself: a holder line overlapping a sample peak is what the member is *for*. What it rules out is the shortcut reading, a component declared to make one misfitting reflection go away — check the phase's scale, profile and preferred orientation first. If the overlap is real, quote the phase quantities and say they overlap |
| `EXTRA_PEAK_NO_INTENSITY` | Quote the declared peak's **centre**, or its esd. The area refined onto its zero bound, so the data does not see the peak — and a peak reaches the pattern only through `area × profile`, so at zero area nothing constrains where it sits either. The centre is a walk, not a measurement: the zero-scale phase's flat direction one rank down (§`PHASE_UNCONSTRAINED`), and why the area's esd comes back absent rather than small. Either the feature is not in this specimen or the centre bounds do not bracket it. Drop the component or move its bounds |
| `ROUGHNESS_ABSORPTION` | Quote roughness and the displacement parameters as two separate results |
| `RESOLUTION_UNCONSTRAINED` | Quote the profile widths, or anything read off them — the crystallite size, the microstrain, `result.microstructure`. U, V and W were refined on a pattern whose peaks are predominantly Lorentzian, where they are not determined by the data, so what they converged to is a fitted artefact rather than a measurement of the instrument. This is McCusker § Synchrotron's named failure, and it carries its own remedy: **measure the instrument instead of refining it here.** `lab_calibrate` on a standard with its certified cell held fixed, `save_instrument_profile`, then `load_instrument_profile` before this fit, which holds all five profile terms. Note what the guard does **not** say: there is no test on how wide the widths are, because the same paper's next paragraph has U, V and W "easily determined" on constant-wavelength neutron data, where the instrument dominates the profile — so one width threshold would have to be wrong for one technique or the other. `value` is the Gaussian's share of the width at the median fitted point |
| `ROUGHNESS_UNCONSTRAINED` / `ROUGHNESS_OUTSIDE_REGIME` | Interpret the roughness parameters physically |
| `PHASE_UNCONSTRAINED` | Quote **anything** about this phase — its cell, its coordinates, its ADPs, its weight fraction — held or refined alike, and in particular do not read a held value as "it did not move, so it is right". `HIGH_CORRELATION` on the same fit reports ρ≈1 between the phase's cell and its scale, which is the symptom; this is the cause |
| `ADP_NOT_POSITIVE_DEFINITE` | Report the tensor as measured |
| `BISO_UNUSUALLY_LARGE` | Read this B as a displacement. At that amplitude an atom in a cell this dense would have melted, so the number is evidence about the **model**: a wrong species or occupancy on the site, an absorption correction that is missing or wrong, or a background flexible enough to have eaten the high-angle intensity that determines B. Check those three before anything else, and check them in that order. The bound is computed from the phase's own cell (Gilvarry 1956). `value` is the refined B and the message carries it as a multiple of the bound. Unlike most rows here this is not an instruction to withhold the number: a genuinely mobile site — a cavity cation, a superionic sublattice — can sit above the bound honestly, and saying *that* is part of quoting it. `Atom.biso` has no default ceiling, so this row is what speaks on a large B |
| `BISO_NEGATIVE` | Do not quote this B as a displacement: the column stands in for something else, and the suggestion lists what to check. `Atom.biso` has no default floor, so a B below zero lands here rather than as `BOUND_HIT` |
| `STEPHENS_STRAIN_NOT_POSITIVE` | Report any S_HKL |
| `RESOLUTION_NOT_POSITIVE` | Quote the profile widths or anything read off them — the crystallite size, the microstrain, `result.microstructure` — and do not trust this fit's own width judgements. Γ_G² = U·tan²θ + V·tanθ + W is a variance, so the constraint is on the quadratic and not on its three coefficients: a negative V alone is ordinary on a focusing geometry, and this fires only where the **sum** goes below zero somewhere in the fitted range. Nothing raises when it does — `gaussian_fwhm` clamps Γ_G to a 1e-4° floor to keep its √ real, so the model reports a resolution four orders finer than any goniometer and goes on converging, and §`HUMP_TOO_NARROW` abstains rather than endorsing a peak it cannot judge against a resolution that is not there. `value` is the worst Γ_G² and the message names the 2θ where it sits and how many fitted points are affected, which on the configuration this was built for is every one of them (the quadratic's roots fall at 0.229° and 168.577° 2θ, outside an ordinary scan on both sides). Refit the resolution on a standard with its certified cell held fixed (`lab_calibrate`), or load an instrument profile and hold it rather than refining U, V and W on this pattern |
| `STRAIN_UNUSUALLY_LARGE` | Quote the strain, the crystallite size derived from the same profile, or that phase's weight fraction **without saying the width is this large** — a strain this far out reaches across the pattern and competes with the background and with any phase it overlaps. Unlike every other row here this is not an instruction to withhold the number, only to adjudicate it |
| `SIZE_UNUSUALLY_SMALL` | Quote the crystallite size, the strain, or that phase's weight fraction **without saying the crystallite is this small** — a size this far out broadens every line and, like a large strain, competes with the background and with any phase it overlaps. Like `STRAIN_UNUSUALLY_LARGE` and unlike every other row here, this is not an instruction to withhold the number, only to adjudicate it |
| `SIZE_NORMALISED_ACROSS_WAVELENGTHS` | (info) Read a shared `phases.N.lor_size` / `gauss_size` from a joint fit as the coefficient **your** histogram shows. It is the coefficient at histogram 0's wavelength; a size coefficient goes as λ (its Gaussian variance twin as λ²), so each histogram's own copy — `MultiHistogramRefinement.fitted_structures[h]` — carries a different number and the message lists them all. The specimen quantity is the crystallite size, which is one number: read it with `rietx.model.profiles.caglioti.apparent_size_from_size_coefficient` and that histogram's own λ, and the answers agree by construction. Nothing is wrong and nothing needs doing; a joint fit that shared the degrees instead would land the implied sizes a factor λ_max/λ_min apart while reporting `converged` |
| `DISPERSION_NEGLECTED` | Quote QPA weight fractions — unequal f′ across phases biases them directly (measured: RMS 2.19 → 0.62 wt % once applied) |
| `NEUTRON_RESONANT_ABSORBER` | Quote an occupancy or a displacement parameter on that site **without first checking this wavelength is away from the resonance**. The neutron twin of `DISPERSION_NEGLECTED`, and the one case where `b_Sears.dat` is incomplete rather than wrong: for Cd, Sm, Eu, Gd and Yb (and their listed nuclides) `b` is *complex* and wavelength-dependent near a nuclear resonance, and the table stores the real part of the thermal value alone. Away from the resonance the thermal value is the right number and nothing is owed, which is why this reports and never refuses. `warning` where the element itself absorbs ≥ 1000 barn (Cd 2520, Eu 4530, Sm 5922, Gd 49700 — a black absorber eats the beam as well), `info` otherwise (Yb 35, whose resonance lives in the minority ¹⁶⁸Yb at 2230). A wavelength-resolved fit may not use one thermal value at all |
| `SPECIES_FALLBACK_NEUTRAL` | Assume the model scatters like the ion its species label names. `crystallography.scattering.normalize_species` substitutes the **neutral atom** when an ion is missing from the Waasmaier-Kirfel table (11 of 111 chemically-real oxidation states — `S6+` and `N3-` among them), reported rather than refused because refusing would break files that refine today. `value` is the fractional error on \|f\| at s = sinθ/λ = 0, and every substitution fires one by default (`refine.SPECIES_FALLBACK_MIN_DELTA_FRAC` raises the floor). It biases occupancies, ADPs and QPA fractions together while barely moving Rwp, so a phase *ratio* can survive it when every absolute wt % is wrong. Silent for a neutron phase, which resolves species through `crystallography.neutron` |
| `HARMONIC_FRACTION` | Transfer the fitted per cent to another histogram, or read it as a property of the specimen. It is a refined scale ratio between two wavelength components of **one** measurement on **one** monochromator, so it is not comparable across instruments and not a material constant. At `warning` level (past 15 %) do not read it as a measurement of the beam at all — the line is absorbing intensity the model puts nowhere, and the tick marks against the unfitted peaks are what to check |
| `HARMONIC_ABSENT` | Read it as a failure of the correction. It is a *result*: the declared λ/n line refined to nothing, which is what a monochromator whose nth order is extinct must give. Dropping the declaration reproduces the fit with one parameter fewer |
| `HARMONIC_HELD` | Quote the harmonic fraction at all — the weight never entered θ, so the number is the value the caller declared, not a measured one. Free `instrument.source.lines.*.weight` in a stage **after** the profile and the scale have settled |
| `ABSORPTION_ESTIMATE_UNAVAILABLE` | Assume the absorption correction ran. It did not; the fit has **no** specimen absorption correction |
| `ABSORPTION_MU_R_OUT_OF_RANGE` | Trust the magnitude of the correction — µR > 1 extrapolates the Rouse fit |
| `ABSORPTION_THICKNESS_MATTERS` | Quote displacement parameters without checking the flat specimen's thickness — part of the correction is not absorbable by the scale and ADPs, so a wrong µt lands in both |
| `ABSORPTION_PLATE_THICKNESS` | (info) Read it as a fit problem — a transmission plate far from µt = 1 costs counts, not accuracy |
| `WAVELENGTH_CALIBRATION` | (info) Quote the cell without saying what pinned the scale the wavelength was measured against — the **held cell** in a single-histogram fit, or which histogram's wavelength was **held** in a joint one. This fires whenever a wavelength was refined, and reports how far it moved from its declared value **in ppm** together with the shift over its own esd. The reference is the wavelength **declared when the refinement was constructed**, so the ppm is the *cumulative* move across successive λ-freeing stages (a `branch` inherits that reference, and a `checkout` to an earlier node never resets it) rather than a delta from the previous stage's answer — only an instrument `edit` re-declares it. It is the only evidence the refinement offers for that move — deliberately not an Rwp comparison. Read a move inside its own esd as "this measured nothing"; read a move far past the beamline's known calibration drift as a modelling error in *that* histogram (an unmodelled harmonic, a zero shift traded against λ) rather than as a calibration result. In a single-histogram fit λ is measured directly against the held cell; in a joint fit the refined cell sits on the scale of the held wavelength, so the held one is part of the number |
| `CAPILLARY_OFFSET_UNAVAILABLE` | (info) Read a cell from this fit as free of position systematics. The eq (4) offsets were held at zero for want of a goniometer radius, and an unmodelled offset moves every axis by the same fraction — so an axial ratio can agree to a few ppm while no axis does (measured: 143 ppm on both axes of a BT-1 refinement, c/a agreeing to 3.4 ppm). It fires on any capillary geometry with no radius, calibrated synchrotrons included (11-BM among them): there the 2θ scale is pinned and a certified cell reproduces to spec, so note it and move on; on a laboratory capillary the same held offset is a real accuracy gap |
| `BRINDLEY_OUTSIDE_REGIME` | Prefer the corrected fractions; past µR ≈ 0.05 the "correction" can be further from truth than none — the QPA round robin's community-wide finding (Madsen et al. 2001; Scarlett et al. 2002: over-correction where none was needed cost more accuracy than the effect it corrects) |
| `MICROABSORPTION_SKIPPED` | Assume microabsorption was handled |
| `PAWLEY_OVERLAP_UNRESOLVED` | Use an individual reflection intensity from the group |
| `PAWLEY_OFF_DATA_RIDGED` | (info) Export or use a named intensity. No emission line of that reflection is centred on the fitted data. It stays in the list so a stage can move it onto the data, but its intensity is ridged toward zero with a width equal to the phase's largest on-data intensity, so the value and its esd are the ridge's, not a measurement. One row per phase. Widen the range if you need them |
| `DATA_SUPPORT_LOW` | Read the esds as the whole story. There are fewer effective observations per structural parameter than the guidelines ask for (at least three, preferably five), and an over-parameterised Rietveld refinement does not fail — it reports large esds while the algorithm's own N, the number of profile *steps*, hides the shortage. `warning` below three, `info` between three and five; the numbers are on `result.data_support` either way, and the message quotes the effective count, the raw reflection count and the parameter count it divided. The remedy is fewer parameters (start from `result.identifiability`), restraints, or a wider 2θ range — never more points across the same peaks, which raises N and nothing else |
| `PATTERN_UNDERSAMPLED` | Quote integrated intensities, ADPs or QPA fractions and expect the step size not to be the limit. The median resolved peak has fewer than five steps across its FWHM, so those intensities were never measured finely enough — and unlike everything else in this table, **no choice made after the fact repairs it**: the counts do not exist. The fit still runs and the number is on `result.data_support`'s companion `PatternDiagnostics.steps_per_fwhm` before any refinement, from `diagnose(data)`. Above ten steps there is no code at all — oversampling costs beam time, not validity |
| `LOW_ANGLE_UNMODELLED` | (warning) Trust the background below the first reflection because `air_scatter_gain` did not fire — it tests the envelope over the *whole* range, which a narrow tail barely moves (Ba₂FeSbSe₅ 1.5 K: 0.019 vs 0.3). This code reads the fit's own residual over `[two_theta_min, first_tick − 2·FWHM)` — every phase, emission line and declared peak, so no peak's low-angle flank is counted, with `first_tick` the lowest image (any line) of a reflection whose window norm ‖y/σ‖ reaches 3σ, so an empty tick (phase at vanishing scale, zero-area peak, zero-|F| reflection) never moves it — and fires when its mean weighted-squared residual exceeds 3× the whole-pattern reduced χ² (`value`). Silent under ten channels in the region. The message names both remedies, raising the lower limit to where the residual falls under 2σ or adding the air term, and picks neither: only someone looking can tell a beam edge from a wrong background |
| `AIR_SCATTER_UNDECLARED` | (warning) Read a P-spline fit's χ² as the background's best without the 1/(2θ) term `auto_background`'s envelope test declines on humped, line-dense data. One-sided score test on the fit's residual: `value` = share of χ² a background refit with the column removes, Bragg held (fires ≥ 0.5 %, ≥ 25× χ²_red). Fires where `LOW_ANGLE_UNMODELLED` can be silent. Remedy: the suggestion |
| `RESTRAINT_TENSION` | Silently accept the averaged compromise — the data and your prior disagree by >3σ |
| `SEQUENTIAL_*`, `SERIES_PATTERN_FAILED` | Look for them in this table. The series codes arrive on a `SeriesResult`, never on one fit. All but one have their rows in §9b, [`references/series.md`](series.md). `SEQUENTIAL_PERSISTENT_FINDING`'s row is in §6, [`references/abstention.md`](abstention.md) |
| `CONSTRAINT_ACTIVE` | (info, the default `lm` driver only; never `trf` or a joint fit) Read the constrained coefficients as free-fit measurements. The driver held steps on a linear-inequality constraint (the message names it: the Stephens cone or the Γ_G² floor) in the answer-producing stage, so the optimum sits on or near its face: admissible, not measured. Vary the start before quoting. It is the *only* signal a declared constraint was active |
| `CELL_DEGENERATE_PROBE` | (info) Read this as anything about the reported values — it is not. `Cell`'s six parameters declare no bounds of their own, so an underdetermined cell stage can drive a trial into a zero- or negative-volume metric; each such trial is refused and answered with a penalised residual, and never enters the reported parameters. `value` counts them over every completed stage, and the message names the stages. Nonzero is ordinary on a poorly-constrained cell |
| `COVARIANCE_UNAVAILABLE` | (warning) Read an absent esd on this result as "that parameter was not refined", or refit to make the warning go away and quote the first fit's values with the second fit's esds. The solve returned; what raised afterwards was the eigensolve behind the esds, so the values are the solver's and every esd, correlation and propagated uncertainty is `None`. `where` names the stage: on the answer-producing one the message says every esd is absent; on an intermediate one only that stage's correlation guard did not run, and a `HIGH_CORRELATION` it would have raised is unknown rather than absent. Refit from these values — fixing or restraining the most correlated block is the usual cure — and quote values and esds from that one fit |
| `CELL_RUNAWAY` | (warning) Read a value it names as measured when it fired in the answer stage: that cell and every path tied to it carry no esd. A free cell left its safety window while solving (±15% for `a`/`b`/`c`, so any length ≤ 0; ±6° for angles), typically degenerate with another free phase's cell. It is pulled back to the window edge after the stage, never as a bound the solver saw (a volumeless phase goes back to its stage-start cell instead; the message says which); one driven only by a free `vars.X` is named, never clamped. Fired earlier: later stages refined it from the edge, so its esd rests on that start. Fix one phase's cell, hold the other, or free the cell in its own stage |
| `HOLD_BLOCKED_PLAN` | (info) Read it as a fault, or the paths it names as measurements. A stage's `turn_on` matched a parameter declared with `Refinement.hold` and the hold won, which is what a hold is for; the value is the one handed in, so it carries no esd and belongs in a report as a constraint (§`PHASE_UNCONSTRAINED`'s rule for a held phase). `StageResult.blocked_by_hold` names them per stage. Read it closely when you did not declare the hold: a reopened `.rex` restores the register, so the plan is doing less than its name says for a reason set elsewhere |
| `STAGE_PATH_UNKNOWN`, `STAGE_PATH_NOT_FREE` | Read the stage it names as having refined what you asked for. A literal `turn_on` path (no `*?[`) or a glob under a retired name named no parameter (UNKNOWN; `StageResult.unknown_paths`), or a literal phase path named a locked or symmetry-tied row, e.g. a special-position `x` (NOT_FREE): nothing was freed for it, yet the fit converged. The message names the nearest path, the current name or the path to free. Fix the plan and refit. Warnings, never raised |
| `PARAMETRIC_OUT_OF_RANGE` | (warning, joint fits) Quote the target at the patterns `where` names: the unbounded coefficients put it outside its own min/max. Narrow the subset or lower the order |
| `STAGE_FREED_NOTHING` | (info, joint fits) Read histogram `value`'s instrument parameters as refined by the stages named. Their globs freed rows of another histogram and matched none of this one — a glob written for one instrument's names (§ 8.28). Nothing is wrong when that histogram declares no such component; otherwise its rows go by other names, so list its `hist.<h>.*` rows and add a glob that reaches them. `StageResult.unreached_histograms` has the globs per stage |
| `QPA_UNAVAILABLE` | Read `result.qpa is None` as "this specimen is single-phase" or as any statement about composition. The refined scales gave a non-positive Σ S·ZMV, so there are no fractions to renormalise — `where` names the scales that died. It is reported rather than raised on purpose: QPA is one field of a result, and raising took a whole 157-pattern sequential run down with one bad pattern |
| `QPA_FRACTION_UNDETERMINED` | (warning — on `FractionProfile.diagnostics`, which `ref.profile_fraction(data, phase)` returns; no fit emits it) Quote the phase's `weight_fraction` ± its esd. Pinning the phase's width on a grid and refitting found fractions the data admits, within Δχ² = 3.84·χ²_red·f² of the lowest χ², more than twice the esd's 95 % half-width from the fit's: the esd is the curvature of the one basin the fit stopped in, and the scale traded against the width until the phase was background. `value` is that distance in half-widths, and the message carries the range and the widths that produced it. Quote the range and the widths, never the point. The basins separate only on information the fit lacks: a width held at a value the specimen justifies, a background that takes the hump itself, or more counts. A silent profile confirms the esd; it does not establish that the phase is present, and a range reaching 0 % says it is not (`judging.md` § "a trace phase's esd describes one basin") |
| `MODEL_FAR_FROM_DATA` | (error) Read `status`, the parameter values or their esds at all. Rwp is past the point where the model is no better than predicting zero everywhere, so this is a mismatch between model and data, not a converged refinement, though `status` may say `converged` (the optimiser's exit: a zero phase scale *is* a minimum once every reflection sits outside its frozen window) and `result.usable` reads False. The message quotes the share of above-background intensity the model actually accounts for (0.2 % on the reproduction); check the cell (~1 % precondition, §1), wavelength, zero shift and 2θ range, then re-index |
| `STAGE_MAX_ITER` | Read the result's `status` as covering every stage — it is the *last* stage's, so a middle stage can stop on its iteration budget while the fit reports `converged`. The named stages did not converge; they ran out. Raising `max_iter` buys solver evaluations, not a different minimum — the stages that stall are the degenerate groups in §3 (measured: three identical mixtures, same models and parameter counts, 39 s / 858 s / 2838 s with no difference in the answer) |
| `FROZEN_COMPILE_STALE` | (info) Read it as a fit defect, or quote the history node's Rwp as the result's. The result's statistics, `y_calc` and residuals are measured on a compile at the values it returns; the last stage solved on a compile whose peak windows and FCJ node counts were frozen at the values it *started* from, and this fires when the two χ² differ by more than 1 % (`value` is that fraction, both figures in the message). The minimum is not biased by it and the esds are the last solve's either way; the history node keeps the frozen figure. A large value says the last stage travelled far enough to re-size its windows, so split that stage if the curve it drew matters. It never aggregates into `SEQUENTIAL_PERSISTENT_FINDING`: it is about how a pattern was measured, not about the model. A Pawley result and a joint fit get no fresh compile, so they report the frozen compile's figures and never carry this row |
| `SPACE_GROUP_SETTING_ASSUMED` | (warning) Read the composition, ZMV or any weight fraction as the one you meant. The phase names a bare Hermann-Mauguin symbol the tables hold in more than one setting (40 of them — the `:1`/`:2` origin choices and the rhombohedral `:H`/`:R` axes), and gemmi resolved it to the first. The site multiplicities differ, so the choice changes how many atoms each site puts in the cell while leaving Rwp untouched: spinel's origin-2 coordinates under a bare `F d -3 m` give Mg2AlO4 where MgAl2O4 was meant. The message quotes the **cell contents each setting implies** — recognise yours and write it into the symbol (`"F d -3 m:2"`). Where the sites that swap carry one species the contents agree, so it quotes the **site multiplicities** instead: Mn3O4 under `I 41/a m d` is Mn12O16 either way and the wrong choice still moves half the intensity. A `:H`/`:R` pair gets alternatives and no composition: different axes. A symbol carrying its setting is silent; what each foreign format can say is in §7g and §7h |
| `SITE_SNAPPED_TO_SPECIAL_POSITION` | (warning — on `result.diagnostics`, and on the reader's channel from `Structure.from_cif(..., diagnostics=[])`) Read the site's multiplicity as the general-position one. The named sites sit within 1e-4 of a special position without being on it (rounding), so their orbit was expanded *at* it: the multiplicity is the special one. Coordinates are **not** rewritten unless the file states the multiplicity (that column, or `_atom_site_Wyckoff_symbol`) and the site is within 1e-3 of the position it names: then the reader **moves** the site there. What changes is the atoms the site puts in the cell, hence ZMV and every weight fraction. The message names each site, its shift and its multiplicity. If they match the source's own multiplicities, nothing is wrong and the coordinates are merely rounded; if they disagree, the coordinates and the space group are telling you different things |

The `TOPAS_*` and `FULLPROF_*` families are **not here**: they belong to
`rietx.io.projects`, they fire at *import* rather than on a fit, and none of
them ever reaches `result.diagnostics`. They have their own file —
§7g, [`references/diagnostics-projects.md`](diagnostics-projects.md) — because
the question they answer comes before a fit exists: *is the model I just
imported the model that file describes?* Load that one if a TOPAS `.inp` or a
FullProf `.pcr` import handed you a diagnostic.

The reader's own family — the `PATTERN_*`, `CIF_*` and vendor-attenuator
rows — is in §7i, [`references/diagnostics-reading.md`](diagnostics-reading.md).
Each fires on a quirk of one file, so load it when a reader handed you a
diagnostic.

The `RECIPE_*` family belongs to the PowderLine
recipe reader (`read_recipe`, `Recipe.diagnostics`) rather than
`result.diagnostics`, and it answers a question the others do not: *how does
the fit I am about to run differ from the one the recipe describes?* It has
its own file too — §7g, [`references/diagnostics-projects.md`](diagnostics-projects.md)
— since a PowderLine recipe is another program's file just as a TOPAS `.inp`
or a FullProf `.pcr` is. Load that one if a PowderLine recipe handed you a
diagnostic.

codes = {d.code for d in result.diagnostics}
if "BACKGROUND_ABSORPTION" in codes:

    ...

# the same measurement as evidence rather than as a bit — and the two
# background hypotheses, which are advice: they change what the background can
# *absorb*, not which parameters move, so there is no stage to run
bg = report.background                      # None only if no background curve
bg.worst_absorption, bg.worst_absorption_path    # 0.46, "…atoms.0.biso"; None = not measured
bg.absorption                                    # every screened path → R²
bg.off_region_chi2_reduced, bg.off_region_durbin_watson   # 12.6, 0.19

report.action("increase_background_flexibility")  # capped at 0.6 — see below

`increase_background_flexibility` is capped however strong its evidence,
because an amorphous hump and an un-modelled broad crystalline phase produce
the same between-peak signature as a too-stiff background, and bending the
background over either of the last two **hides** it while improving every
statistic. `add_impurity_phase` rides in its `alternatives` for that reason,
and each names the other. If you add the flexibility anyway, read any QPA
afterwards as fractions of the crystalline content you did model.
